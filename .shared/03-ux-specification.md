# 03-ux-specification.md — Personalized Weekly Mission UX

## 1. 使用者旅程 (User Journeys)

### A. 週一打開擴充功能

1. 使用者開啟 popup。
2. 看到「本週任務卡」與當前進度（例如 0/3 任務）。
3. 點擊「前往複習」進入 review。
4. 完成題目後收到 `Mission +1` 回饋。
5. 回到 popup，進度條同步更新。

### B. 閱讀中被動學習

1. 使用者在網頁閱讀內容。
2. 命中本週弱項詞彙時，高亮 tooltip 顯示 `Mission` 標記。
3. 使用者 hover 看到翻譯與難度，形成「任務關聯」認知。
4. 若收藏新詞，`discover_new_words` 任務立即增加。

### C. 任務完成與結算

1. 主任務全部達成後，popup 顯示完成狀態。
2. history 顯示本週成就摘要與連續週數。
3. 系統預先生成下週推薦難度。

## 2. 關鍵互動規範

- 任務進度更新時機:
  - 收藏成功: 即時
  - Review 作答完成: 即時
  - 啟動 extension 或切週: background 重算
- 單次提示頻率:
  - 同詞、同頁、同 session 最多顯示一次 `Mission` 標記
- 失敗回復:
  - 任務資料讀取失敗時，UI 顯示靜默降級（不阻斷核心翻譯/高亮功能）

## 3. 個人化策略 UX

- 向使用者顯示「為何推薦」:
  - 例:「你上週在 B1 詞彙正確率偏低，建議先補 5 個弱項詞。」
- 難度調節可預測:
  - 不突增任務量；每週變化控制在 +/-20%
- 新手保護:
  - 初期僅推 1-2 個小任務，避免壓力

## 4. 邊界案例

| 案例 | UX 處理 |
|---|---|
| 詞彙不足 (<10) | 顯示「先收藏幾個單字來啟用任務」 |
| 全部任務已完成 | 顯示慶祝狀態 + 建議進階挑戰 |
| 未授權通知 | 不彈錯誤，僅顯示「可開啟提醒」開關 |
| 使用者關閉高亮 | 任務仍可透過 review/history 進行 |
| 跨時區 | 以本地裝置時區計算週期 |

## 5. 可用性與可及性

- 任務進度條需有文字百分比，避免只靠顏色。
- 所有任務按鈕可鍵盤操作，支援 `aria-label`。
- 小尺寸 popup 優先顯示「下一個最重要任務」，其餘可展開。

## 6. 成功體驗定義

- 使用者 3 秒內理解「本週要做什麼」。
- 使用者在一次 session 內至少完成 1 個任務步驟。
- 使用者不覺得任務提示干擾主要閱讀流程。
